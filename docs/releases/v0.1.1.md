# Neo v0.1.1

> Release channel: Stable
>
> Tag: `v0.1.1`
>
> Date: 2026-07-25 (UTC)

Neo v0.1.1 is the first stable release in the v0.1.1 line. It supersedes
`v0.1.1-rc.1+20260721.0406` and `v0.1.1-rc.2+20260721.0634`.

All four Neo workspace packages now use the standard SemVer version
`0.1.1` without a prerelease or build-metadata suffix. The RC tags remain
immutable historical release records.

## v0.1.0 Baseline

`v0.1.0` established Neo's first distributable baseline:

- Local-only Rust CLI and TUI with no hosted backend, account, or telemetry.
- OpenAI Responses, Anthropic, Google, and OpenAI-compatible providers.
- Permission-gated built-in file, shell, terminal, planning, goal, and task
  tools.
- Resumable and forkable workspace-scoped JSONL sessions.
- Layered skills, MCP server support, queue-and-steer interaction, and
  macOS/Linux/Windows release binaries.

The `v0.1.0` GitHub Release did not include a written changelog; this section
records that baseline explicitly for comparison.

## v0.1.1 Highlights

- Prepared multi-file Edit and Write executions use a prepare, approve,
  stale-check, and commit lifecycle with truthful partial-commit reporting.
- Durable RunWorkflow execution now has a journal-backed runtime with
  replay/rehydration and explicit paused or failed states.
- Shell and terminal execution is more inspectable: admission remains pending
  while queued, terminal input is ordered, and captured output is bounded and
  sanitized.
- Delegate, DelegateGroup, and DelegateSwarm activity now exposes bounded,
  replay-safe file and tool summaries while preserving the existing card UI.
- Session, provider, MCP, compaction, RPC, and cross-platform filesystem paths
  received release-hardening fixes.
- The release lifecycle supports stable and unstable channels, self-update,
  uninstall, rollback protection, and platform asset validation.

## Added

- Prepared batch Edit with ordered `files[]`, `replacements[]`, and
  `expected_matches`, instruction probes, Plan-mode validation, typed approval
  data, progress events, stale rechecks, and partial commit states.
- Prepared batch Write with multi-file authorization, approval presentation,
  bounded summaries, replay-safe Delegate details, and a documented `files[]`
  contract.
- Durable workflow capability, journal, limit, runtime, and recovery modules;
  workflow notifications and launch/replay coverage accompany the runtime.
- Stable/unstable update modes, release asset selection, binary version checks,
  self-replacement safeguards, uninstall handling, and release-workflow tag
  validation.
- Incremental RPC response streaming and live compaction progress events.
- Delegate file-activity rows, tool-activity summaries, elapsed-time display,
  and replay-safe transcript presentation.
- Append-only skill catalog snapshots, host metadata validation, atomic built-in
  skill refreshes, and non-blocking instruction import cycles.
- Cross-platform durable directory/session-index handling and native-path
  preservation for Windows.

## Changed

- Provider credentials are scoped to their provider; credential-bearing headers
  remain sensitive throughout request construction.
- Session and durable-file writes use a single atomic-file owner, including
  Windows-safe locking and replacement behavior.
- SSE framing, provider URL validation, shell ANSI handling, terminal frames,
  and captured logs now share bounded and sanitized paths.
- Resume, compaction, task-browser, transcript-overflow, and live-renderer
  behavior retain complete historical state without changing Delegate-family
  card layout or expansion semantics.
- Edit streaming token accounting counts only replacement content, and large
  mismatch readbacks identify incomplete snapshots and the next read offset.
- The PTY dependency remains on `portable-pty 0.9.0` to preserve Linux ARM64
  compatibility without raising the minimum glibc version.

## Fixed

- Hardened prepared Edit and Write authorization, stale-input detection,
  replay, durable synchronization, and write-root enforcement.
- Prevented duplicate transcript snapshots, lost compaction progress, dropped
  RPC output, abandoned spawned turns, and completed cancellation bridges.
- Preserved todos and context footer state across compaction and resume; removed
  exit blank gaps and kept transcript overflow scrolling responsive.
- Stabilized task-browser navigation, completed Bash command retention, shell
  admission accounting, terminal control input, and streaming output framing.
- Fixed Windows session-index locking, launch-barrier path handling,
  notification encoding, and release-build dependency classification.
- Fixed Linux ARM64 release linking by avoiding the `xpty` `close_range` glibc
  symbol requirement.
- Recovered stale JSON-store locks, prevented blocking persisted-task reads, and
  made child resume failures explicit instead of silently continuing.
- Resolved Rust 1.97 Clippy and stale regression expectations that blocked the
  repository CI workflow.

## Security and Safety

- Provider credentials and authorization headers are treated as sensitive data.
- Edit and Write operations are authorized against workspace/write roots and
  revalidated immediately before commit.
- Shell and terminal output/control paths use bounded capture, sanitization, and
  ordered input to reduce truncation, injection, and resource-exhaustion risk.
- Windows notification text is base64-encoded before insertion into PowerShell,
  preventing untrusted text from becoming script syntax.
- Update and uninstall paths verify binary identity and protect against unsafe
  replacement, rollback, or interrupted self-update states.

## Verification

The release verification gate is the repository's formatting, lint, build,
unit/integration, and release-target checks. The tag-triggered release
workflow is responsible for the final six-platform archive build and
publication:

- `cargo fmt --all --check`
- `cargo clippy --workspace --all-targets --all-features -- -D clippy::all`
- `cargo build -p neo-agent`
- `cargo nextest run --workspace --all-features`
- Linux x86_64/ARM64, macOS x86_64/ARM64, and Windows x86_64/ARM64 release
  builds from `.github/workflows/release.yml`

This source checkout was locally verified with `cargo fmt --all --check`,
`cargo check -p neo-agent`, and the lifecycle release-policy regression test
`modes::lifecycle::tests::release_selection_enforces_channel_and_downgrade_policy`.
