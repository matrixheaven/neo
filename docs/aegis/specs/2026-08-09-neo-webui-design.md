# Neo WebUI 设计

Date: `2026-08-09`

Status: `已确认，待书面评审；不授权实现`

## 1. 目标

为 Neo 增加名为 `neo-webui` 的本机网页界面。它是现有本地 Coding Agent 的另一个交互入口，不替代终端界面、标准输入输出 RPC、会话记录或运行时。

首版必须同时满足：

1. 大面积聊天工作区、左侧工作区会话列表、顶部工作摘要和改动入口。
2. 多个会话可以同时运行；切换、归档、关闭网页和网页长连接断开均不得取消后台回合。
3. 网页只允许本机访问，默认终端输出含令牌的完整访问地址并自动打开浏览器。
4. 思考、工具、终端、审批、提问、子代理和助手正文都投影自 Neo 的真实事件。
5. 会话历史、系统提示、缓存前缀和规范事件保持追加式，网页不得创建第二份可改写历史。
6. 前端和底层可由两个执行者分别完成，文件边界和网页协议明确且互不侵入。

## 3. 范围与非目标

### 范围

- 新增 `neo webui` 命令。
- 新增 Rust 包 `neo-webui`，承载本机网页服务、网页协议和打包后的静态资源。
- 新增网页前端，采用 TypeScript、React 和本地 CSS；运行时不得访问第三方网页、字体、脚本或图片。
- 现有会话元数据增加置顶和归档状态。
- 在 `neo-agent` 中新增网页会话宿主，复用现有回合、审批、提问、取消和事件路径。

### 非目标

- 不开放局域网、公开地址、反向代理、隧道或远程协作。
- 不替换 `neo rpc`，不增加网页到旧 RPC 的转发或兼容分支。
- 不增加网页删除会话。
- 不增加第二套 `AgentRuntime`、第二套会话记录、第二套任务清单或第二套工具执行路径。
- 不在网页中展示提供方密钥、原始配置、全局会话索引或任意磁盘路径。
- 不改变终端界面中 Delegate、DelegateGroup、DelegateSwarm 的卡片语义、层级或展开规则。

## 4. 页面与交互

### 4.1 桌面骨架

```text
+----------------------+------------------------------------------------------+
| Neo                  | 工作区 / 当前会话 / 当前工作摘要          改动 | 分支 |
| 新会话               +------------------------------------------------------+
| 搜索                 | 当前改动文件路径                            +37 -26 |
|                      +------------------------------------------------------+
| 会话分组             |                                                      |
|  - 当前会话          |                  转录工作画布                    |
|  - 其他会话          |                                                      |
|                      |                [可折叠任务清单]                  |
|                      |          [悬浮半透明圆角输入框]                  |
+----------------------+------------------------------------------------------+
```

- 顶部高度固定为 `48px`。左侧显示工作区路径、当前会话摘要、运行状态与耗时；右侧只显示变更入口与分支状态。
- 顶部不得显示模型、权限或开发模式。这些选择属于当前输入，放在输入框的工具行。
- 有编辑活动时，顶部下方出现当前变更条，显示文件路径和增加、删除统计；点击后从右侧覆盖打开改动视图，不永久压缩聊天区。
- 没有改动时不展示空白占位或设置工具条，保留分支状态即可。
- 左栏默认 `280px`，最小 `224px`，最大 `420px`。分隔条可拖拽，键盘左右键也可调整。只有宽度这一项可以保存在浏览器本地偏好中。

### 4.2 会话列表

- 顶部有新会话和会话标题搜索。首版搜索仅匹配会话标题，不建立全文搜索索引。
- 排序为：已置顶、普通会话按更新时间倒序、归档会话单独查看。
- 会话行展示标题、最近更新时间与动态状态：空闲、运行中、等待确认、等待回答、失败。
- 悬停显示置顶与归档图标；点击这些图标不得切换当前会话。
- 右键菜单与键盘菜单提供重命名、置顶或取消置顶、归档或取消归档。
- 归档运行中的会话只改变列表位置，绝不停止模型、工具、终端或子代理。

### 4.3 聊天与输入

- 新会话仅显示 Neo 标识和输入框，置于主区视觉中心偏下；不放营销文案或技术说明。
- 第一条消息发送后，同一个输入框平滑移动到聊天区底部上方 `16px`，成为悬浮编辑器。
- 输入框宽度为 `min(760px, 主区宽度减 48px)`；窄屏为主区宽度减 `16px`。
- 输入区最小高度 `52px`、最大高度 `180px`。达到上限后仅输入区内部滚动。
- 表面使用半透明深色、轻微背景模糊、细边框和低阴影；不使用底部分割线、渐变或装饰性卡片。
- 转录区预留输入框与任务清单的最大高度，输入框覆盖内容时不遮住最后一条消息。
- `Enter` 发送，`Shift+Enter` 换行，中文输入法组合态不能触发发送。
- 输入框工具行从左到右为附件入口、逐条确认、开发模式；右侧为当前运行状态、模型与推理选择、圆形发送按钮。没有端到端能力的按钮不展示。
- 会话运行中，普通发送进入后续输入队列；立即引导和停止当前回合必须是独立且可辨识的操作，不能替换普通发送语义。

### 4.4 悬浮任务清单

- 任务清单锚定在输入框正上方，和输入框同宽、同一视觉轴；展开时向上生长，不推动输入框。
- 收起时显示任务进度与当前进行项；展开时显示所有当前任务和真实状态。
- 没有任务时完全隐藏。展开状态只属于当前浏览器会话，不写入会话元数据。
- 任务清单只投影最近的 `AgentEvent::TodoUpdated`，网页不得编辑、勾选、删除或伪造任务状态。

### 4.5 转录与滚动

- 用户消息靠右；助手正文靠左且不套大卡片；代码块提供复制操作。
- 思考默认折叠，进行中显示状态；展开后展示 Neo 原始内容与真实顺序。
- 工具、终端与工作流条目使用紧凑摘要；展开后显示参数、命令、结果、耗时、排队位置和真实截断标记。
- 排队事件必须显示“排队等待”，不能伪装为完成或超时。
- 审批和提问留在转录原位置，处理结果追加到同一条目的状态中。
- Delegate、DelegateGroup、DelegateSwarm 保持现有层级和内容，不简化为通用任务卡。
- 用户离开底部查看历史时，新事件不抢滚动位置，只在输入框上方显示回到最新内容的浮动操作。

### 4.6 响应式与无障碍

- 小于约 `980px` 时左栏转为抽屉；小于约 `720px` 时仅保留单列聊天区。
- 右键菜单有键盘等价入口；分隔条、折叠条、发送、停止、审批和提问按钮均可键盘聚焦。
- 运行状态不能只依赖颜色，必须同时具备文字和辅助说明。

## 5. 包边界与依赖方向

```text
neo-agent
  -> neo-webui
       -> neo-agent-core

neo-agent-core
  -X-> neo-webui

neo-webui
  -X-> neo-tui
```

### `neo-webui`

- 提供本机 HTTP 服务、网页长连接、鉴权、静态资源、网页协议和请求大小限制。
- 定义 `WebUiCommand`、`WebUiReply`、`WebUiSnapshot`、`WebUiEventEnvelope` 与唯一的 `WebUiHost` 边界。
- 不读取 JSONL，不创建运行时，不执行工具，不解析全局配置。

### `neo-agent`

- 实现 `WebUiHost` 的唯一实现 `WebSessionHost`。
- 负责配置解析、会话调度、`TurnChannels`、审批、提问、取消、模型与权限的逐回合覆盖。
- 复用 `run_prompt_streaming` 与 `run_prompt_in_session_streaming`，不得创建网页专用运行时。

### `neo-agent-core`

- 保持 `AgentEvent`、会话 JSONL、任务事件、工具输出引用、会话标识验证和会话元数据的现有位置。
- 会话元数据新增 `pinned` 和 `archived`，缺失旧字段默认 `false`。
- 不依赖网页类型，不接受网页路径或网页凭据。

`WebUiHost` 虽然首版只有一个实现，但它是避免 `neo-webui` 反向依赖二进制包所必需的唯一跨包边界。除它之外不得新增包装层、适配器层或同义命名。

## 6. 启动、监听与安全

### 6.1 启动行为

```text
neo webui
```

- 只绑定 `127.0.0.1:0`，由系统分配端口。禁止 `localhost`、`0.0.0.0`、局域网地址和自定义绑定地址。
- 监听成功后生成仅驻留内存的 32 字节随机访问令牌，并在交互式终端输出：

```text
打开地址：http://127.0.0.1:<端口>/#access=<一次性令牌>
```

- 同时使用现有 `webbrowser` 能力打开该完整地址。浏览器打开失败不得停止服务。
- 输出被重定向时不得打印令牌，避免令牌进入文件、持续日志或持续集成输出。

### 6.2 令牌与会话凭据

- 地址片段中的令牌不会发往服务端。网页读取后调用 `POST /api/auth/claim`，令牌只可成功兑换一次。
- 成功后服务端生成独立随机会话凭据，设置：

```text
HttpOnly; SameSite=Strict; Path=/
```

- 本机 HTTP 不能诚实地设置 `Secure`，不得伪装为已启用。安全基础是回环绑定、一次性令牌、精确来源校验和不持久化凭据。
- 网页成功兑换后立即调用 `history.replaceState` 清除地址片段。
- 令牌、会话凭据、认证请求体、网页长连接帧和 `Set-Cookie` 不得出现在普通日志、错误文本、会话 JSONL、浏览器本地存储或崩溃转储辅助文本中。
- 服务退出立即使会话凭据失效。

### 6.3 请求防护

- 静态资源和令牌兑换入口可匿名访问，但不返回会话、配置、工具或文件数据。
- 其他接口要求有效会话凭据。
- 所有请求必须精确匹配实际主机；所有写请求与网页长连接还必须精确匹配来源：

```text
Host: 127.0.0.1:<实际端口>
Origin: http://127.0.0.1:<实际端口>
```

- 缺失或不匹配的主机一律拒绝。写请求或网页长连接的来源缺失、为 `null` 或不匹配时一律拒绝。不开启跨域响应头。
- 所有 API、认证页面和转录响应使用 `Cache-Control: no-store`、`Referrer-Policy: no-referrer` 与 `X-Content-Type-Options: nosniff`。
- 内容安全策略只允许本站脚本、样式、连接、数据图片和本地预览；禁止外部资源、内联脚本、嵌入框架和基础地址改写。
- 网页长连接使用 Cookie 与精确来源校验，不复制参考项目把持久令牌写入子协议头的方式。

### 6.4 威胁边界

完整地址在首次兑换前属于临时访问凭据。能读取终端滚动记录、截图或同一账户浏览器的人可能在此窗口内使用它；一次性兑换缩短该窗口。已被同机高权限程序或恶意浏览器扩展控制的环境，不属于网页鉴权能够保护的范围。

## 7. 网页接口

所有 JSON 字段使用 `snake_case`，首版只支持这里列出的当前路径，不增加历史路径或别名。

```text
GET   /api/bootstrap
GET   /api/sessions?scope=active|archived&query=&cursor=&limit=
POST  /api/sessions
GET   /api/sessions/<session_id>/snapshot
POST  /api/sessions/<session_id>/turns
POST  /api/sessions/<session_id>/input
POST  /api/sessions/<session_id>/cancel
POST  /api/sessions/<session_id>/approval
POST  /api/sessions/<session_id>/question
PATCH /api/sessions/<session_id>
GET   /api/sessions/<session_id>/tool-output/<output_ref>?start_line=&max_lines=
GET   /api/events
```

### 7.1 读取模型

```json
{
  "session_id": "...",
  "title": "...",
  "updated_at": "...",
  "pinned": false,
  "archived": false,
  "state": "idle"
}
```

- `bootstrap` 返回当前工作区、可选模型、逐条确认选项、开发模式选项和初始会话摘要；不返回提供方密钥、完整配置或绝对路径。
- `sessions` 只返回会话摘要。标题搜索由服务端在现有会话元数据中完成，不能扫描完整会话内容。
- `snapshot` 返回指定会话的规范历史投影、当前回合状态、待审批项、待提问项、最近任务清单和会话元数据。

### 7.2 写入模型

```json
{
  "message": "...",
  "composer": {
    "model": "...",
    "reasoning_effort": "...",
    "permission_mode": "ask",
    "development_mode": "normal"
  }
}
```

- `POST /api/sessions` 用第一条消息创建会话并启动首回合；没有消息的新会话只存在于网页草稿中，不产生空会话文件。
- `POST /turns` 只允许空闲会话启动新回合。
- `POST /input` 接受 `delivery: follow_up | steer`；运行中的普通发送使用 `follow_up`。
- `cancel`、`approval`、`question` 都必须携带当前 `turn_id` 和对应待处理项标识。过期或不属于该会话的操作一律拒绝。
- `PATCH` 只允许修改标题、置顶和归档。网页没有删除入口。
- 工具输出接口只接受既有 `ToolOutputRef` 对应的不透明引用，并验证它属于路径中的会话；不得接受任意文件路径。

### 7.3 网页长连接

浏览器建立 `GET /api/events` 后先发送订阅消息：

```json
{
  "type": "watch_session",
  "session_id": "...",
  "after": {
    "stream_id": "...",
    "sequence": 42
  }
}
```

服务端事件统一为：

```json
{
  "type": "session_event",
  "stream_id": "本次服务启动标识",
  "session_id": "...",
  "sequence": 43,
  "event": {}
}
```

- `sequence` 在一个会话和一次服务启动内单调递增。
- 当前被查看的会话接收完整 `AgentEvent`；其他会话只推送状态和元数据变化，避免多个后台会话把完整转录压入浏览器内存。
- 切换会话时网页发送新的 `watch_session`。服务端先建立事件接收点并记下切换序号，再生成快照；发送快照后补发更晚事件，不能产生丢失窗口。
- `stream_id` 不同、缓存不足或序号无法续接时，服务端返回完整快照并重新开始当前会话序号。

## 8. 会话调度、持久化与内存

### 8.1 回合调度

- `WebSessionHost` 以会话标识为键持有网页会话执行器。
- 同一会话同一时刻只能有一个主动回合，避免上下文在写锁前并发回放、写入器争用和工作流事件路由覆盖。
- 不同会话使用独立执行器并行运行。
- 网页连接不是 `AgentEventStream` 的持有者。后台宿主必须持续消费流、更新状态、持久化和广播；断开连接只移除观察者。
- 逐条确认、计划模式、目标模式、模型和推理设置只作用于对应会话的对应回合，不得静默修改其他活跃会话的共享状态。

### 8.2 追加式记录

- `AgentEvent` 是唯一事件语义来源。网页只增加会话标识、服务启动标识与序号，不改名、不转换为旧 RPC 事件、不重写顺序。
- 正常事件继续走既有 JSONL 持久化路径。网页实时中继不能另写一份规范 JSONL。
- 重试期间的临时模型输出按照现有重试语义清除；失败尝试不能成为最终历史。
- 任务清单从最后一条 `TodoUpdated` 恢复；工具完整输出从 `ToolOutputRef` 分页读取。

### 8.3 有界中继

- 每个活动会话只保留有界的最近事件缓存；建议上限为每会话 `256KiB`、全服务 `4MiB`。
- 单个事件超过会话缓存剩余空间时不缓存，重连改走快照。
- 每个网页连接使用有界发送队列。慢客户端达到上限后关闭连接，客户端重连并请求快照；不得累积无限队列。
- 完整工具与终端输出不复制进入事件缓存，始终经输出引用按需读取。
- 这些边界不得改变规范 JSONL、模型上下文或原有工具生命周期。

## 9. 验收

### 安全

1. 只能绑定 `127.0.0.1`，任何局域网、通配符和公开地址配置都被拒绝。
2. 终端交互模式输出完整地址；输出重定向时不输出令牌。
3. 地址片段兑换成功后被清除；第二次兑换失败；服务退出后 Cookie 失效。
4. 错误主机、错误来源、缺失来源的写请求和网页长连接均被拒绝。
5. 日志、错误和持久化文件不含访问令牌、Cookie 或认证请求体。

### 运行时

1. 两个会话能并行运行；切换会话不停止任一回合。
2. 同一会话第二条普通输入排队；只有明确引导会走引导路径。
3. 网页长连接断开后，工具、终端、子代理和模型回合继续完成。
4. 重连后不重复显示事件，不遗漏事件；缓存不足时快照恢复正确。
5. 审批、提问、取消都拒绝过期或跨会话操作。
6. 置顶和归档跨重启保存；旧会话默认未置顶、未归档。
7. 工具输出引用不能越权读取其他会话或任意路径。

### 网页

1. 宽屏下聊天区占主要面积，左栏可拖拽，顶栏显示工作摘要与改动入口。
2. 输入框半透明悬浮，不存在底部横线固定栏。
3. 任务清单悬浮在输入框上方，可折叠且反映真实任务事件。
4. 会话悬停、右键、置顶、归档、窄屏抽屉和键盘操作均可用。
5. 思考、工具、排队、审批、提问、终端和子代理的状态与 Neo 事件一致。

## 10. 实施顺序与交接

1. 底层执行者先创建 `neo-webui` 的网页协议、宿主边界、会话调度、安全服务和精确测试，并交付固定的网页数据样本。
2. 前端执行者只在 `crates/neo-webui/web/` 内实现界面，使用固定数据样本完成布局、交互和浏览器验证。
3. 协调者把二者接入后，验证真实多会话、断线、审批、工具输出和视觉表现。

两份可直接交接的说明位于：

- `docs/aegis/handoffs/2026-08-09-neo-webui-frontend.md`
- `docs/aegis/handoffs/2026-08-09-neo-webui-runtime.md`
