# Neo 运行时内存有界化设计

Date: `2026-08-08`
Status: `approved for implementation`

## 1. 目标

Neo 在超长会话和多子任务场景下，常态内存目标为 `300-500MB`。修复必须消除随事件数量线性增长的内存持有，不能依赖重启、历史截断、系统参数、定时清理或关闭重试。

本设计只处理四个已证实的增长点：

1. 交互流将每个 `AgentEvent` 同时发送到界面，并再次保存在 `PromptTurn.events` 直到主回合结束。
2. 子任务每个文字或思考增量都深拷贝完整 `AgentSnapshot`，再通过无界通道排队。
3. `SessionEventPersistence` 为重试安全克隆并保存每个流式增量，直到胜出消息正式追加。
4. `ModelTurnState` 每收到一个文字或思考增量，都重建并复制此前的完整累计字符串，制造二次方级分配流量和分配器高水位。

## 2. 决定性证据

- PID `47366` 的系统分配器约有 880 万个存活对象、约 `3.5GB` 分配，调查期间从约 `2.4GB` 增至约 `3.6GB`。
- 当前会话磁盘总量约 `21MB`，排除“历史文本本身占满数 GB”。
- `AgentEvent` 为 `672` 字节；当前回合事件向量容量 `262144`，单个向量分配精确为 `168MiB`。
- `AgentActivityEntry` 为 `224` 字节；完整快照的 24 条活动记录每次深拷贝约 `5376` 字节，与堆中大量约 6KB 对象吻合。
- `MultiAgentRuntime::apply_child_event` 对每个 `TextDelta` 和 `ThinkingDelta` 返回变化；直接子任务随后复制完整快照并发出 `DelegateUpdated`。
- 界面 `TranscriptStore` 原位更新同一张子任务卡片，不是卡片累计导致的增长。
- 当前二进制没有旧 `mimalloc` 符号；PID `81789` 的分配器问题已经修复，但不是 PID `47366` 的当前根因。
- 旧 `ModelTurnState` 对单字符增量执行 `String::from` 和 `Arc<str>` 重建；15 万次累计搬运约 `10.5GiB`，30 万次约 `41.9GiB`。

## 3. 需求就绪检查

- 需求来源：用户要求给出最优方案并直接实施，常态内存不超过 `300-500MB`。
- 用户场景：长会话、约 15 万条增量、多个同时运行与累计完成的子任务。
- 验收：峰值不超过 `500MB`，回合结束不超过 `300MB`；增量数量翻倍时保留对象数不再线性增长。
- 硬约束：追加式上下文、缓存前缀、重试胜出语义、会话顺序和现有子任务卡片保持不变。
- 开放阻断问题：无。
- 结论：`ready`。

## 4. 最优方案

### 4.1 流式回合返回小结果

为交互和 RPC 流新增小型结果，只包含：

- `session_id`
- `assistant_text`
- `event_count`

事件仍实时发送并按现有规则持久化，但不再同时放入回合级 `Vec<AgentEvent>`。非流式 CLI 的 `PromptTurn.events` 保持不变，因为 JSON/文本输出和现有测试确实消费它。

### 4.2 子任务进度使用现有轻量事件并限频

复用已经存在的 `AgentProgressSnapshot`、`DelegateProgressUpdated` 和 `DelegateSwarmProgressUpdated`：

- `DelegateStarted` / `DelegateFinished` 继续携带完整快照。
- 运行中更新只携带轻量 `AgentProgressSnapshot`。
- `TextDelta` / `ThinkingDelta` 最多每 `33ms` 发布一次；快照本身仍逐事件更新，因此下一次发布包含截至当时的完整累计状态。
- 工具排队、开始、更新、结束，重试状态和其他结构边界立即发布。
- 最终 `DelegateFinished` 始终刷新最后状态，最后一个文字增量不会丢失。

这将生产速度限制为每个活跃子任务最多约 30 个文字进度事件每秒，而不改变文字内容、工具状态或卡片布局。

### 4.3 子任务结果增量汇总

删除 `ChildRunOutput.events`。`run_agent_snapshot` 在消费事件时只累计最终需要的固定结果：

- 最后一条完整助手文本；
- 累计 token 使用量；
- 成功、失败或取消状态；
- canonical messages。

工具数、活动、最新文本和 token 计数继续由 `MultiAgentRuntime` 内的现有快照逐事件更新。最终状态从该快照生成，不再第二次扫描和保存原始事件全集。

### 4.4 重试尝试原位合并相邻增量

`SessionEventPersistence` 继续延迟提交当前模型尝试，但在 `attempt` 内原位合并：

- 同一回合的相邻 `TextDelta`；
- 同一回合的相邻 `ThinkingDelta`；
- 同一回合、同一工具调用的相邻 `ToolCallArgumentsDelta`。

其他结构事件保持原顺序。失败尝试仍整体丢弃，胜出尝试仍在 `MessageAppended` 时一次追加。合并只改变内部批次粒度，拼接后的字节内容和重放结果不变，缓存前缀与 canonical messages 不变。

### 4.5 模型正文使用活动缓冲区

`ModelTurnState` 的当前文字和思考片段使用可增长的 `String` 原位追加，只在片段结束或消息结束时转成现有 `Content`。事件仍逐个发出，最终消息内容、片段顺序、思考编号和签名保持不变。

## 5. 否决方案

- 只删除 `PromptTurn.events`：仍会保留每个子任务完整快照和重试增量，无法解决根因。
- 把所有通道简单改成固定容量：会在生产者等待时改变工具和终端生命周期，且不能决定哪些事件可合并。
- 磁盘暂存每次重试：可行但需要新的临时文件生命周期和异步回放路径；相邻增量原位合并已能把对象数从增量数量降到结构边界数量。
- 限制历史、子任务总数或强制重启：掩盖增长，不满足用户目标。
- 修改子任务卡片：界面存储已原位更新，不是根因。

## 6. 兼容边界

- 不改写或截断既有会话文件。
- 不改变 `AgentMessage`、provider 请求、缓存前缀或消息顺序。
- 不关闭重试，不提交失败尝试。
- 不启用微压缩或去重裁剪。
- 不改变 Delegate、DelegateGroup、DelegateSwarm 卡片设计。
- 不新增用户配置、后台清理器、依赖或平台专用实现。
- `DelegateUpdated` 旧持久化变体继续可重放；新运行中进度统一走已有轻量变体。

## 7. 验收

1. 15 万条相邻增量在重试批次中合并为常数个结构事件，拼接内容完全一致；失败批次仍丢弃。
2. 直接子任务和 swarm 子任务的文字进度发布数量由运行时间决定，不随增量数量增长；工具与最终边界完整。
3. 流式回合返回事件计数但不保存事件全集；RPC 的 `event_count` 保持准确。
4. 子任务结构化输出和 token 使用量不再依赖原始事件向量，结果不变。
5. 使用隔离 `NEO_HOME` 的本机压力重放中，约 15 万条增量和 4 个并发子任务峰值不超过 `500MB`，结束不超过 `300MB`；增量翻倍不再产生同规模事件/快照保留。

本机最终结果：15 万条峰值和结束值均为 `109.12MiB`；30 万条峰值 `212.38MiB`、结束值 `189.56MiB`。15 万条相对旧版 `468.00MiB` 峰值下降 `76.7%`，相对旧版 `233.16MiB` 结束值下降 `53.2%`。

## 8. 风险

- 时间门控若误吞工具边界，会让卡片状态滞后；实现只门控文字和思考增量，并用现有轻量进度事件测试工具边界。
- 合并持久化增量若跨过事件类型或工具调用边界，会改变重放；实现仅合并严格相邻且键相同的增量。
- 本机 RSS 受编译器、调试构建和系统缓存影响；仓库内提交确定性对象数量测试，RSS 阈值作为隔离 release 二进制的本机验收证据。
