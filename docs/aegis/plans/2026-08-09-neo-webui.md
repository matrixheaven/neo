# Neo WebUI 实施计划

状态：设计已由用户书面确认；本计划不单独授权代码实现。

## 目标

新增 `neo webui` 和 `neo-webui` 本机网页入口。它必须保留 Neo 的原有终端界面、标准输入输出 RPC、会话 JSONL 与运行时；多个会话能够并行运行，浏览器切换、归档和断线均不得终止后台回合。

## 架构

```text
neo-agent
  -> neo-webui
       -> neo-agent-core
```

- `neo-webui` 只持有回环 HTTP 服务、网页长连接、鉴权、静态资源、网页数据形状和有界发送队列。
- `neo-agent` 的 `modes/webui/` 持有唯一的 `WebSessionHost`，复用 `TurnChannels` 与 `run_prompt_*_streaming`，负责回合、审批、提问、取消、后续输入、会话状态和事件中继。
- `neo-agent-core` 继续是 `AgentEvent`、JSONL、会话标识验证、工具输出引用和会话元数据的唯一持有位置。
- 浏览器只消费 `WebUiHost` 的强类型网页接口，绝不读取 JSONL、配置、密钥或文件系统路径。

## 技术栈

- Rust 2024、Tokio、现有 `axum`、`rand`、`base64`、`async-trait` 与 `webbrowser`。
- TypeScript、React、Vite、本地 CSS 和本地打包资源；不在运行时访问第三方脚本、字体、图标、图片、分析或遥测服务。
- Cargo Nextest、现有假模型与隔离临时目录；前端状态测试和真实浏览器自动化截图。

## 兼容边界

- `neo rpc` 保持标准输入输出入口；网页不得调用、包装或转发它。
- 系统提示、缓存前缀、规范历史、`AgentEvent` 顺序、提供方请求和 JSONL 记录保持追加式。
- 不改动 `neo-tui`，不改变 Delegate、DelegateGroup、DelegateSwarm 的语义、层级或展开行为。
- 不开放自定义地址、局域网、公开地址、反向代理或隧道。
- 首版没有网页删除会话、网页全局配置写入、网页任务编辑或第二套会话数据库。

## 计划检查

### 需求就绪检查

- 需求来源：用户对三节设计的书面确认，以及 `docs/aegis/specs/2026-08-09-neo-webui-design.md`。
- 用户场景：本地编码代理需要可同时观察多个后台会话的网页界面；工作区以聊天为主，输入框与任务清单悬浮，安全地址方便终端直接打开。
- 验收：设计说明第 9 节的安全、运行时和网页验收项全部有对应实施任务与验证。
- 开放阻断：无；当前只缺用户对代码实施的明确授权。
- 结论：`ready`。

### 基线使用草案

- 必需依据：`AGENTS.md`、基线治理、运行时内存有界化设计、WebUI 设计和两份交接。
- 已在计划前查看：全部必需依据及 `run_prompt_streaming`、`run_prompt_in_session_streaming`、`TurnChannels`、`SessionMetadataStore`、`ToolOutputStore::read_range`。
- 本计划引用：本节“依据”中的全部文件。
- 缺失依据：无。
- 结论：继续。

### 改动必要性

- 用户可见需求：网页入口必须安全地显示真实会话、后台回合、审批和工具活动。
- 不改代码的方案：现有 `neo rpc` 只能串行读取标准输入输出请求，且没有会话订阅、审批、断线续接或浏览器鉴权，不能满足需求。
- 最小改动边界：新增 `neo-webui`，在 `neo-agent` 加入网页会话宿主和命令行入口，在现有会话元数据加入两个布尔字段。
- 结论：`code-change`。

### 新表面存在性检查

- 拟新增表面：`neo-webui` 包、`WebUiHost`、网页协议和本地前端。
- 可复用位置：现有 RPC、TUI、会话 JSONL 和 `AgentRuntime` 都不具备网页安全或多会话订阅职责。
- 新增证明：`WebUiHost` 是阻止 `neo-webui` 反向依赖 `neo-agent` 的唯一窄接口；`WebSessionHost` 是既有运行时私有装配能力的唯一网页适配位置。
- 熵控制：不创建网页运行时、网页 JSONL、网页配置或网页到 RPC 的桥接；同一语义只保留 `AgentEvent` 一份。
- 结论：`add-with-proof`。

### 架构完整性检查

- 不变式：网页连接永远不是 `AgentEventStream` 的持有者；后台宿主持续消费流并将结果投影给浏览器。
- 唯一持有位置：网页传输在 `neo-webui`，会话执行在 `neo-agent`，规范事件和持久化在 `neo-agent-core`。
- 避免的重叠：不把 `AppConfig`、`AgentRuntime`、工具、会话路径或凭据暴露给网页包；不在前端推断事件语义。
- 更高层简化：每会话一个执行器直接复用已有流式回合函数，不新增全局任务调度器或二次消息存储。
- 结论：按此边界实施。

### 旧路径与持久化治理

```text
Anti-Entropy Declaration:
- Deletion Class: contract-carrying code and persistent-state metadata are touched, but no object is deleted.
- Old Path/Object: neo rpc remains the existing standard-input/output entry.
- New Canonical Owner: neo-webui owns browser transport; neo-agent owns browser session execution.
- Expected Preserved Behavior: neo rpc, JSONL history, and existing session metadata remain usable.
- Expected Retired Behavior: no WebUI-to-RPC bridge, no duplicate event store, no browser-local session database.
- External Boundary Touched: yes, neo rpc is an existing CLI entry.
- Source-of-Truth Data Risk: none; pinned and archived are additive metadata fields with serde defaults.
- User Confirmation Required: no destructive action is planned.
```

```text
Retirement Decision:
- Path: compat-exception
- Why: the existing standard-input/output entry has a distinct published use; it remains separate instead of acquiring a second browser behavior path.
- Non-edits: do not remove old session fields, JSONL events, RPC methods, or user session files.
```

验证必须同时证明网页新入口可用、旧 RPC 没有被网页接入、旧会话缺少新字段时默认值正确、网页不能访问任意路径或跨会话工具输出。

### 复杂度预算

- 目标文件：新增的 `crates/neo-webui/**`、`crates/neo-agent/src/modes/webui/**` 与现有小型命令、会话元数据位置。
- 当前压力：`modes/interactive` 和 `modes/run` 已经很大，网页代码不得继续塞入其中。
- 推荐边界：网页宿主独立为 `modes/webui/`；服务按 `auth.rs`、`protocol.rs`、`server.rs`、`relay.rs` 分离；前端只在 `web/` 内。
- 结论：`within-budget`，前提是 `WebUiHost` 仍是唯一跨包边界，任何第二个网页适配器或事件存储都应停止并回到本计划。

## 执行批次

### 任务 1：建立网页包、接口共识与回环安全服务

**文件：** `Cargo.toml`、`crates/neo-webui/Cargo.toml`、`crates/neo-webui/src/{lib.rs,protocol.rs,auth.rs,relay.rs,assets.rs,server.rs}`、`crates/neo-webui/tests/webui_behavior/{auth.rs,relay.rs}`。

**原因：** 先把网页传输和安全边界固定，前端与运行时随后只依赖同一份强类型接口和固定事件样本。

**最小改动：** 新建一个网页包；不得在 `neo-agent-core` 引入 Axum，也不得把网页请求直连到旧 RPC。

**步骤：**

1. 在工作区加入 `neo-webui`，复用工作区的 `axum`、`tokio`、`serde`、`serde_json`、`rand`、`base64`、`async-trait`、`uuid`、`tracing` 和 `neo-agent-core`；仅补足网页套接字所需的 `axum` 特性，不另加 HTTP 框架、浏览器启动库或令牌库。
2. 在 `protocol.rs` 定义 `WebUiHost`，其唯一方法组为“执行 `WebUiCommand`”与“订阅某会话的网页事件”；定义 `WebUiCommand` 的 `bootstrap`、会话列表、快照、首条消息、新回合、后续输入、取消、审批、提问、元数据修改、工具输出范围读取和订阅变体。所有字段按设计第 7 节使用 `snake_case`，会话标识、回合标识和待处理项标识都用独立强类型字段，禁止自由路径字符串。
3. 定义 `WebUiEventEnvelope { stream_id, session_id, sequence, event }`，其中 `event` 直接承载 `AgentEvent`，不重命名、不降级为旧 RPC 事件；定义 `WebUiSnapshot` 同时包含规范历史投影、当前状态、待处理项、最近任务、元数据和续接信息。
4. 在 `crates/neo-webui/fixtures/webui-events.json` 交付规范固定样本，至少包含新会话、助手正文、思考、排队工具、终端、审批、提问、重试、任务、三个 Delegate 系列事件、改动统计和断线快照。该文件一经前端开始使用即成为只读输入，字段或顺序不足时由底层补齐，不在前端猜测或兼容。
5. 在 `auth.rs` 用 `TcpListener::bind("127.0.0.1:0")` 绑定随机端口，生成 32 字节一次性令牌。令牌仅存在内存的可消费槽位；`POST /api/auth/claim` 成功后立即消费它，签发独立随机 Cookie，并返回不包含令牌的响应。
6. 为所有请求精确校验实际 `Host`；为所有写请求与网页长连接精确校验实际 `Origin`。把 Cookie 校验、`Cache-Control: no-store`、`Referrer-Policy: no-referrer`、`X-Content-Type-Options: nosniff` 和严格内容安全策略收敛为一个中间件路径；不添加跨域响应头。
7. 在 `relay.rs` 实现按会话递增的 `sequence`、每会话 `256KiB` 和服务整体 `4MiB` 的事件缓存、每连接有界发送队列。单事件过大或缓存不足时标记需要快照；慢连接满队列时关闭连接，绝不积压无界消息。
8. 在 `server.rs` 逐条实现设计说明中的当前路由。先注册观察者并记录序号，再取快照、发送快照、补发之后的事件；`stream_id` 改变、序号缺失或缓存不足必须回退完整快照。完整工具和终端输出只传现有输出引用，范围读取交给宿主。
9. 当前端执行者交付 `web/dist` 后，将固定前端资源以编译期字节嵌入 `assets.rs`。Vite 输出固定的 `index.html`、脚本和样式文件名，已打包资源随源码提交；服务端不得从当前工作目录或任意用户路径读取网页文件。
10. 创建 `webui_behavior` 行为测试，使用随机端口、内存假宿主和无敏感内容的捕获日志。逐项验证一次性兑换、Cookie 属性、错误主机、错误或缺失来源、无 Cookie 的网页长连接、安全响应头、缓存溢出快照和重复序号拒绝。

**验证：**

```bash
cargo test --package neo-webui --test webui_behavior -- webui_behavior::auth::claim_consumes_the_one_time_token_and_sets_a_strict_http_only_cookie --exact --nocapture
cargo test --package neo-webui --test webui_behavior -- webui_behavior::auth::write_and_websocket_requests_reject_wrong_or_missing_origin --exact --nocapture
cargo test --package neo-webui --test webui_behavior -- webui_behavior::relay::overflow_falls_back_to_a_snapshot_without_unbounded_queue_growth --exact --nocapture
cargo clippy -p neo-webui --test webui_behavior -- -D clippy::all
```

### 任务 2：在唯一会话元数据位置加入置顶和归档

**文件：** `crates/neo-agent-core/src/session/mod.rs`、`crates/neo-agent-core/src/session/test_cases/metadata.rs`。

**原因：** 置顶和归档必须跨重启保存，但不能变成网页本地假状态或第二份数据库。

**最小改动：** 只扩展现有元数据结构与锁保护写入；不改 JSONL `AgentEvent`，不迁移或重写旧会话文件。

**步骤：**

1. 在 `SessionRecord` 和 `StoredSessionMetadata` 增加 `pinned: bool`、`archived: bool`，两个字段均标注 `#[serde(default)]`，确保旧元数据读取为 `false`。
2. 扩展现有 `records_from_metadata` 投影，使列表、标题、更新时间和新字段来自同一会话元数据文件；不要在网页层排序时写回状态。
3. 在 `SessionMetadataStore` 的现有验证与锁保护写入路径中新增一个只接受标题、置顶和归档的元数据更新方法。拒绝不存在或非法会话标识；不接受文件路径、全局会话索引或任意键值。
4. 扩展现有元数据测试，证明缺失字段读取为 `false`，一次置顶或归档跨新建 `SessionMetadataStore` 仍保留，非法标识不创建元数据。

### 任务 3：实现网页会话宿主和命令行入口

**文件：** `crates/neo-agent/Cargo.toml`、`crates/neo-agent/src/cli.rs`、`crates/neo-agent/src/main.rs`、`crates/neo-agent/src/modes/mod.rs`、`crates/neo-agent/src/modes/webui/{mod.rs,host.rs,session.rs}`、`crates/neo-agent/tests/webui_behavior/{session_runtime.rs}`。

**原因：** 现有 `run_prompt_streaming` 与 `run_prompt_in_session_streaming` 已具备正确的会话与运行时装配；网页必须在这一层复用它们，而不是创建第二个运行时。

**最小改动：** `modes/webui/` 是网页会话的唯一动态持有者。它仅使用现有 `TurnRequest`、`TurnChannels`、`SteerInputHandle`、审批与提问通道，不改动 TUI 或 RPC。

**步骤：**

1. 增加 `neo webui [--no-open]`。服务监听成功后，默认和 `--no-open` 都在交互式终端打印完整 `http://127.0.0.1:<port>/#access=<token>` 地址；默认调用 `webbrowser::open`，`--no-open` 只禁止自动打开。输出被重定向时不得打印令牌；打开失败只报告不含凭据的错误且服务继续运行。
2. `WebSessionHost` 为每个会话保存一个执行器：活动 `JoinHandle`、取消令牌、`SteerInputHandle`、待审批、待提问、逐回合配置快照、当前状态、最近 `TodoUpdated` 与到 `neo-webui` 的事件发布器。执行器只在明确取消或进程关闭时取消。
3. 新会话首条消息通过 `run_prompt_streaming` 启动；已有会话空闲时通过 `run_prompt_in_session_streaming` 启动。运行中普通输入进入现有后续输入队列；只有明确的 `steer` 使用 `SteerInputHandle`。同一会话第二次启动必须返回排队或冲突状态，绝不能并行创建第二个写入器。
4. 每个后台任务独占消费它的 `AgentEventStream`，将规范事件先按既有路径持久化，再更新状态和发布网页事件。浏览器取消订阅、关闭标签页或网页套接字断开只能移除观察者，不能丢弃流或取消工具、终端、子代理与模型。
5. 构造每回合覆盖时，复制 `controller_callbacks` 已有模型、推理、权限、工作区策略、计划模式、目标模式、指令注册表和主题草稿处理方式；覆盖只属于该会话当前回合，不得改写其他会话或全局 `AppConfig`。
6. 审批、提问和取消都验证“会话标识 + 当前回合标识 + 待处理项标识”。`ToolOutputRef` 的范围读取先验证会话归属，再调用 `ToolOutputStore::read_range`；任何非法引用、跨会话引用或路径形式输入均拒绝。
7. 由 `SessionMetadataStore` 提供会话摘要、标题搜索、置顶与归档。搜索只匹配标题，归档运行中的会话只改变列表归属且继续发送动态状态。
8. 用假模型和同步屏障建立产品边界测试：两个不同会话同时开始并各自完成；同会话第二条普通输入没有平行回合；移除唯一网页订阅后后台回合仍完成；过期审批、提问、取消和工具输出引用被拒绝。

### 任务 4：按固定网页接口实现工作区界面

**执行者边界：** 前端执行者只允许写入 `crates/neo-webui/web/**`，在任务 1 的 `protocol.rs` 与固定事件样本交付后即可并行开始，不需要等待网页宿主或服务完成。不得改动 Rust、Cargo、旧 RPC、TUI、会话文件、固定样本或设计说明。

**视觉主张：** 深色、克制、连续工作的工作区；聊天画布占主区绝大部分面积，边界和动效只服务于会话、输入和实时状态，不把它做成营销页或卡片仪表盘。

**信息与互动主张：** 顶部只用于工作摘要、改动入口和分支；左侧只用于会话；主区只用于转录和悬浮输入。输入框从新会话的视觉中心平滑移动到会话底部，任务清单在其正上方展开，右键菜单、悬停操作与拖拽分隔条为会话管理提供直接反馈。

**文件：** `crates/neo-webui/web/{package.json,package-lock.json,tsconfig.json,vite.config.ts,index.html}`、`crates/neo-webui/web/src/{main.tsx,app.tsx,api.ts,types.ts,styles.css}`、`crates/neo-webui/web/src/components/**`、`crates/neo-webui/web/src/state/**`、`crates/neo-webui/web/src/tests/**`、`crates/neo-webui/web/dist/**`。

**最小改动：** 一个 React 应用、一个按会话分片的前端状态、一个网页长连接重连路径。不得增加浏览器端会话数据库、全量后台转录缓存、令牌持久化或事件语义猜测。

**步骤：**

1. 建立锁定依赖的 Vite 与 React 工程。只安装构建、React、图标和测试所需依赖；所有图标本地打包，生产页面禁止外部网络请求。构建输出使用固定文件名，以便 Rust 的 `assets.rs` 编译期嵌入。
2. 在首屏只从地址片段内存读取一次 `access`，调用认证入口，成功后立即用 `history.replaceState` 清除片段。令牌、Cookie、请求体和错误对象均不得写入本地存储、会话存储、控制台或遥测。
3. 实现顶栏、可拖拽左栏、会话搜索和归档视图。左栏默认 `280px`、最小 `224px`、最大 `420px`；只将宽度保存为本地无敏感偏好。悬停置顶归档和右键或键盘菜单执行同一接口，操作不得切换当前会话。
4. 以会话标识分片保存转录条目、事件游标、草稿、展开项、滚动位置、运行状态、待审批项和待提问项。当前会话订阅完整事件，其他会话只保留摘要状态；`stream_id + sequence` 去重，服务端要求快照时清空该会话的派生视图后按快照重建。
5. 将 `AgentEvent` 明确投影为用户消息、助手正文、思考、工具、终端、审批、提问、重试、任务与子代理条目。增量以稳定事件标识原位更新；失败尝试由服务端事件撤除，前端不得用正则或视觉推测归类。
6. 实现新会话居中标识与同一输入框。首条消息后它移动为底部上方 `16px` 的半透明圆角悬浮编辑器，输入高度为 `52px` 到 `180px`，到上限后内部滚动；`Enter` 发送、`Shift+Enter` 换行，中文输入法组合态不发送。
7. 将附件、逐条确认、开发模式放入输入框工具行；模型与推理、运行状态、圆形发送和停止操作位于右侧。所有控件只在后端已有对应能力时显示。顶部不能出现模型、权限或开发模式，也不能出现底部横线分隔栏。
8. 只从最近的 `TodoUpdated` 投影任务清单；任务清单与输入框同宽并锚定其上方，可折叠、向上增长、没有任务时隐藏，且不能编辑任务。用户查看历史时，新事件只出现回到最新内容的悬浮操作，不能抢走滚动位置。
9. 实现改动入口的右侧覆盖视图、紧凑工具和思考展开、真实排队提示、代码复制、审批与提问原位处理。Delegate、DelegateGroup、DelegateSwarm 必须保留后端事件提供的层级和内容。

11. 只读使用任务 1 的固定事件样本写前端状态回归，覆盖两个会话切换、重连快照、重试撤回、任务清单、队列、审批和提问。验证认证成功后调用 `history.replaceState` 清除地址片段。用真实浏览器自动化在桌面、窄桌面和手机宽度截图，确认没有重叠、截断、空白主区、底部固定横线或令牌残留在地址栏。
12. 运行前端构建并更新已打包的本地资源；随后检查构建后的网页不引用外部 URL，确保嵌入资源与源代码一致。

## 执行路线

- 决定：`subagent-driven`。
- 依据：底层 Rust 与前端目录所有权互斥；前端只依赖底层先交付的协议样本，随后可以与网页宿主并行；第三位执行者只做集成与安全复核，不改动两侧主体文件。
- 分派：底层执行者先交付任务 1 的网页数据形状和固定样本，随后继续任务 1 的服务、任务 2 和任务 3；前端执行者在样本交付后负责任务 4；协调者或独立复核执行者负责任务 5。
- 回退：任何接口字段不足、会话配置无法隔离、工具输出无法验证归属或事件快照无法无丢失续接时，停止对应任务并报告最小缺口。
- 用户确认：需要。用户须明确授权“按本计划开始实现”，才可以创建或修改 `neo-webui`、运行时和前端代码。
