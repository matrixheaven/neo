# 测试套件治理反思

- 测试数量不是根因证据；本机一小时必须拆成冷编译、热执行和串行资源组。
- 统一结构不能强迫私有测试公开，也不能通过增加顶层文件制造更多测试二进制。
- 最小可靠方案是现有 Rust 工具链、语义去重、明确文件边界和精确 Nextest 调度；无需新依赖。
- 远端快速结果不能覆盖用户本机事实，最终验收必须使用同一台本机的前后数据。
- 文档工作完成不等于测试治理实施完成。
- 固定迁移拓扑和提交状态机比增加治理工具更能抑制长任务漂移；本方案没有新增检查器、标签或台账。
- 旧 ADR 的格式失败不等于决策失效。先做引用与替代关系分类，避免用删除掩盖校验错误。
- 当前交接只把真正需要证据的删除与串行归类留给执行阶段，其余目录、命名、命令和停止条件均已锁定。
